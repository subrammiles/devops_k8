# minikube
Minikube is not just another Docker image. It is a tool that runs a small, local Kubernetes cluster on your computer.
Minikube allows you to run Kubernetes locally without needing a cloud platform such as AWS or Azure.

Normally, a Kubernetes cluster might run on several servers:
- A control plane manages the cluster.
- Worker nodes run your applications.
Minikube lets you create a small Kubernetes cluster on your own computer for learning and development.

2.minikube start
kubectl get nodes

You should see a node named something like minikube with status Ready.

What does Ready mean?

It indicates that Kubernetes considers the node ready to run workloads.

Your Ubuntu machine has Docker, and Minikube runs a Kubernetes cluster.You can make the image available to Minikube by running:
minikube image load my-node-app:1.0

Then check the images available in Minikube:
minikube image ls
output:
docker.io/library/my-node-app:1.0

This tells you that the image is also available in Minikube's image store.

Therefore, your image is already available in both places.

- Pod: The smallest deployable unit in Kubernetes.
- Container: Runs your application inside the Pod.
- Application: Your Node.js code, such as app.js.
In your example, the Pod contains one container running your Node.js application.

# 
Can a Pod contain multiple containers?
Yes! For example:
             Kubernetes Pod
           ┌───────────────────┐
           │                   │
           │  Container 1      │
           │  Node.js app      │
           │                   │
           │  Container 2      │
           │  Log collector    │
           │                   │
           └───────────────────┘

Containers in the same Pod share the Pod's network namespace, including its IP address, and can communicate through localhost. They can also share configured storage volumes.

However, most simple applications start with one container per Pod.
